# Job Copilot code review — 15 October 2026

Historical findings. Current behavior and release checks are documented in
[engineering.md](engineering.md); later changes supersede this snapshot.

## Executive Summary

Reviewed the actual Python/FastAPI/SQLAlchemy/Alembic backend, React dashboard,
served legacy dashboard, WXT/TypeScript extension, adapters, and tests. The goal
is a single-user local application assistant, with candidate data stored in
SQLite and selected generation context sent directly to Gemini.

The local architecture fits that goal. The previous passing tests did not cover
several security and data-integrity failures. The corrections below are applied
in source and the unpacked extension build. This is not a production-readiness
certification: live Chrome/ATS checks remain deferred, and the React deployment
path still differs from the dashboard actually served.

## Critical Issues (Must Fix)

### 1. P1 — Host-page scripts could activate privileged buttons — fixed

`extension/src/content.ts` accepted every click on its DOM buttons. A job page
can find an injected button and call `click()`, triggering profile autofill or
an AI request without a real user click. Both handlers now require
[`event.isTrusted`](https://developer.mozilla.org/en-US/docs/Web/API/Event/isTrusted). Popup and Chrome shortcut dispatch still use extension
messaging. The unauthenticated page `postMessage` toast relay was removed;
toasts use the existing background relay. Regression tests cover synthetic and
trusted handler invocation. Real Chrome event behavior still needs verification.

### 2. P1 — Matcher fabricated eligibility, preferences and education — fixed

`backend/field_matcher.py` returned Yes for visa/work authorization, consent,
and unknown choices. Relocation ignored the saved preference; `_handle_yes`
selected Yes even when passed No. Missing education produced a specific
university, degree, GPA, scale and dates. A requested bachelor's degree could
fall back to a master's record.

Eligibility/consent matching and generation now require manual answers. Boolean
options honor the requested value; unmatched options remain unresolved. Missing
education is skipped, degree levels are not substituted, and notice periods
use saved values. Phone matching no longer interprets “Tell me…” as “tel”. Salary
matching distinguishes 15 from 150; experience ranges accept “2 to 5”. These
changes intentionally favor leaving fields blank over inventing candidate facts.

### 3. P1 — Delayed responses could fill the wrong field — fixed

`extension/src/content.ts` looked up mutable `data-jc-index` attributes after an
API request. Mutation/scroll rescans could reassign those indices. The second
fill pass also used a different setter path, bypassing first-pass exclusions
and select/checkbox handling.

`extension/src/core/autofill.ts` now captures element references, field identity,
question context, values and document URL before the request. Detached, changed,
hidden, password and user-edited targets are skipped. Both passes share the
same application logic. Pending AI responses receive the same stale-target
check. Checkbox activation clicks once without pre-setting `checked`; radio
filling preserves an existing group selection. Counts reflect the setter result.

### 4. P1 — Description fallback included form content — fixed for known containers

Selected containers stripped forms, but the generic body fallback returned raw
page text. Prefilled textarea contents or editable drafts could enter Gemini
context or the application log. `extension/src/adapters/helpers.ts` now uses the
same filtered text traversal for both paths. It excludes forms/ARIA forms,
controls, labels, editable regions, hidden markers and extension UI, with limits
on visited nodes and returned text. It avoids cloning the entire body. Arbitrary
unmarked personal text on a page cannot be identified reliably by these filters.

### 5. P1 — Profile updates allowed ORM mass assignment and malformed JSON — fixed

`backend/profile_manager.py` used `hasattr` followed by `setattr`, allowing a
request to change `id` or ORM attributes and store JSON with an invalid shape.
`backend/profile_validation.py` now validates all supplied writable values
before creating/updating a row. It checks education/certification objects,
skill lists, scalar types and bounds, retaining the JSON-in-TEXT storage format.
Read-only/unknown keys are ignored for compatibility with dashboard round trips.
Invalid updates return 422 without partially saving the other fields.

### 6. P1 — Loopback binding lacked a Host boundary — fixed

The server returned profile data when sent a non-local Host header. It also
used CORS response policy without checking Origin on actual API requests.
`backend/server.py` now applies TrustedHostMiddleware for localhost/127.0.0.1
and `backend/security.py` rejects untrusted non-preflight Origins. Existing
CORS preflight behavior remains. Host-header rejection is tested; a browser
DNS-rebinding exploit was not attempted. No-Origin local clients remain
supported: this is still an unauthenticated local service, not remote auth.

### 7. P2 — Worker exposed an arbitrary cross-origin fetch proxy — fixed

`extension/src/background.ts` forwarded arbitrary URLs and RequestInit options.
`extension/src/core/api-proxy.ts` restricts requests to the configured localhost
origin and an endpoint/method allowlist, strips caller-supplied headers/options,
rejects redirects and credentials, and sets a 60-second client deadline. This
reduces the authority exposed if a content-script message path is compromised;
it does not imply that ordinary websites can directly send runtime messages.
This follows [Chrome's guidance on limiting content-script network access](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests#limit-content-script-access-to-cross-origin-requests).

### 8. P1 — Offline AI answers invented personal anecdotes — fixed

`backend/ai_writer.py` substituted detailed first-person stories about incidents,
latency and employment history when AI was unavailable or output was rejected.
It now returns an explicit error and the extension leaves the textarea alone.
The prompt forbids invented personal facts. Logger initialization is also moved
to module scope so a successfully initialized client can log a later failure.
Tests that required fabricated fallback anecdotes now require safe failure;
valid generated technical answers and prompt construction remain tested.
Generation still needs candidate review; prompting cannot guarantee truth.

### 9. P2 — DOM setters silently corrupted values or selected unrelated options — fixed

`inputMode="numeric"` caused telephone numbers to be parsed as a single numeric
fragment. Scalar identifiers were truncated to fit length limits. Every setter
scheduled a global dropdown search that fell back to its first item.
`extension/src/core/dom.ts` now normalizes only number inputs, leaves incompatible
scalar values blank, scopes autocomplete to the active unchanged control and
its associated/nearby menu, and requires an exact option match. Essay length
limiting remains. Some provider-specific dropdowns may consequently need manual
selection until their adapters implement an explicit association.

### 10. P2 — Tracker UI reported failed writes as saved; legacy URL validation was bypassed — fixed

Both dashboard implementations updated local application state after HTTP 4xx
responses because fetch does not reject those statuses. React now uses
`frontend/src/api.js`; the served `backend/static/index.html` also checks response
status and restores the status picker after failure. Failed notes saves show an
error. The legacy application logger now shares HTTP(S) URL validation with v1;
both UIs avoid turning older unsafe-scheme values into links.

## Improvements & Refactoring

- **Release/deployment gap:** FastAPI serves `backend/static/index.html`, currently
  the legacy dashboard. Vite builds React into `backend/static_staging`; `start.sh`
  does not promote it. Establish one documented build/serve path after checking
  feature parity. This review corrects the active legacy tracker as well as React
  source; it does not silently replace the dashboard.
- **Tracker vocabulary:** Migrate the UI to `/api/v1/applications` and its allowed
  transitions. The legacy API deliberately maps draft to applied, so its labels
  cannot prove an application was submitted.
- **Performance:** Removed duplicate AI-button scanning and repeated reinjection
  requests for unchanged iframe elements. Description traversal is bounded. The
  body-wide observer and modal `innerText` scans still need profiling and narrower
  roots. Background frame injection is still serial and repeated CSS injection
  can remain across explicit dispatch/navigation paths; measure before introducing
  bounded parallelism and per-document injection tracking.
- **ATS lifecycle:** Mutation observation now includes iframe `src` and relevant
  field attributes. Hostname matching is classification, not authorization. The
  broad manifest permissions remain; optional per-site host grants are a separate
  onboarding/security improvement. Workday/Ashby remain generic fallbacks.
- **Runtime contracts:** Form metadata is now bounded/validated before matching,
  and malformed payloads return 422. Continue converting other legacy AI/export
  Dict bodies to public Pydantic schemas and make error responses consistent.
- **AI runtime:** Configure a backend model-call deadline and classify retryable
  SDK errors. The worker deadline does not cancel synchronous backend generation.
  Keep the model configurable; no live model availability or billing test was run.
- **Data layer:** Keep SQLite/Alembic. JSON storage itself is not obsolete;
  validation matters more than normalizing without a query requirement. Consider
  enforcing the singleton profile and extension-log deduplication with database
  constraints if concurrent creation becomes possible; query-then-insert alone
  is not an atomic uniqueness guarantee.
- **Code organization:** The adapters are a useful boundary, but generic company
  and degree heuristics still make assumptions. Add confidence/manual-review UX,
  factual profile fixtures, and measured accuracy cases. Extract remaining custom
  modal logic incrementally rather than introducing another broad framework.
- **Validation gap:** Add real Chromium tests for site grants, cross-origin frames,
  framework event reconciliation, autocomplete, SPA transitions, and trusted
  clicks before claiming live ATS reliability. No shadow-DOM coverage is claimed.
