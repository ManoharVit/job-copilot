# Engineering hardening review — 22 October 2026

## Assessment
The existing project already had automated tests, strict extension TypeScript,
local database isolation, Host/Origin checks and explicit permission recovery.
Those controls did not cover the defects below. This release hardens their
negative paths and adds reproducible CI checks; it does not certify the entire
application as production-ready. The unsourced 90%/91% claims supplied in the
request are not used as evidence.

## Corrections

| Finding | Evidence and correction |
| --- | --- |
| AI retry amplification and no explicit provider timeout | Application retry/model loops multiplied SDK attempts. Removed these loops; configured 10-second SDK request timeout, two SDK attempts and at most two concurrent generation calls. Permanent failures no longer trigger alternate guessed models. |
| Invalid/unbounded AI/export payloads | Dict bodies allowed wrong scalar/list types to reach processing. Strict Pydantic contracts now bound all writer/export fields; general write bodies are capped at 512 KiB even when streamed without Content-Length. Resume upload retains its separate bounded path. |
| Generation failure presented as success | Offline/failing writers returned original text, templates, error text or fallback content under HTTP 200. Failures now return 503. Provider exception text is not returned. Dashboard AI helpers reject HTTP errors, malformed results and error sentinels before changing drafts or showing success. |
| Export header and plain-text encoding weaknesses | Profile/document labels entered Content-Disposition without safe tokenization, and TeX metacharacters were incompletely escaped. Filenames are sanitized/quoted; all TeX metacharacters are encoded as text. The endpoint never invokes a compiler. |
| Private response/error handling | Profile and other API responses lacked a general no-store policy; legacy validation could echo rejected values. API privacy headers now apply, and validation details omit submitted input. Versioned oversized-body errors retain the v1 envelope and request ID. |
| Incomplete startup artifact check and stale deployment script | An assets directory was treated as a complete build. The validator checks the React root, JS/CSS references, non-empty files and path containment. Startup rebuilds broken bundles. deploy.sh builds/validates the current directory instead of requiring removed staging assets. |
| Dependency advisories | Python audit reported certifi 2026.7.22 and Pillow 12.3.0; frontend audit reported Vite 8.3.2. Locks now select certifi 2026.10.19, Pillow 13.0.0 and Vite 8.3.4. Published SHA-256 hashes were retained/refreshed; other Python versions were preserved. A resolver dry run validated both locks. |
| Optional Docker interface exposure | Database and frontend ports were published on every host interface. Their published ports now bind to 127.0.0.1. Docker execution was not tested. |
| Incomplete CI gates | Added backend security lint, tracked-file privacy/credential-pattern checks, dependency advisory audits, dashboard lint and artifact validation to the existing test/type/build jobs. |

Security lint has one narrowly scoped S608 exception: the static CANONICAL values
in an already-applied historical migration. The migration code was preserved;
its SQL fragment uses no request input. Schema validation now uses an explicit
exception rather than an optimization-removable assert.

## Local evidence

- Backend: **287 tests passed**, including negative paths, migrations and export
  generation, using isolated databases and patched certifi/Pillow wheels.
- Dashboard: **24 tests passed**; ESLint and Vite 8.3.4 build passed.
- Extension: **189 checks passed** (182 Node tests, four standalone extraction
  scenarios and three compiled-bundle tests); strict TypeScript/build passed.
- General Python lint and backend security lint passed. Both shell entrypoints
  passed syntax checks. Dashboard references and source credential-pattern checks
  passed. No real profile, resume or .env edits are part of this release.
- Runtime Python, dashboard and extension advisory scans reported **no known
  vulnerabilities** for the updated locked versions at the time of this scan.
  Advisory matching is not proof of exploitability or proof of absence of flaws.

## Remaining limits and review work

- Real Chrome permission prompts, ATS event reconciliation, SPA transitions and
  actual resume uploads still require the controlled pilot in engineering.md.
- No paid Gemini request or factual-accuracy benchmark was run. Generated text
  still needs candidate review. Prompt instructions cannot guarantee truth.
- There is no authentication for remote or multi-user hosting. Local processes
  under the user's account remain trusted. No public deployment is authorized.
- SDK timeout is not an exact total wall-clock cancellation guarantee. Provider
  requests can continue after a browser closes its request.
- UI-wide draft persistence across tab changes, tracker vocabulary migration,
  custom dropdown/shadow-DOM coverage and observer profiling remain separate work.
- Existing dependency deprecation warnings remain. Secret detection covers only
  listed filenames and recognizable credential formats, not all possible leaks.
- A hosted GitHub Actions run and an independent human/model security review were
  not performed here. CI configuration and local checks are not those reviews.

## Working agreement
Use the [spec](specs/engineering-hardening.md) and [engineering workflow](engineering.md)
for new work: acceptance criteria, focused failing reproducer, bounded correction,
negative-path checks, reviewed diff, and recorded live validation. Do not use
passing unit tests as evidence for unrelated browser or product-demand claims.
